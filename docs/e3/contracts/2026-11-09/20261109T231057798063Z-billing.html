Facturación

Las facturas se emiten y se pagan por un servicio SOAP. Esta guía explica cómo autenticarse, las cuatro operaciones, cuándo se puede emitir, cómo se calculan los intereses y qué facturas recibe cada grupo.

Acceso y autenticación

Endpointhttps://dev.proyecto.2026-2.tallerdeintegracion.cl/soap/billing
WSDL/soap/billing?wsdl
Namespacehttp://billing.tallerdeintegracion.cl
Límite60 requests por minuto por IP.

Cada request lleva un header WS-Security UsernameToken con el número de tu grupo como Username y el secreto de tu grupo como Password (texto plano; usa siempre HTTPS). Las operaciones actúan siempre sobre el grupo autenticado. 

<soapenv:Header>
  <wsse:Security xmlns:wsse="http://docs.oasis-open.org/wss/2004/01/oasis-200401-wss-wssecurity-secext-1.0.xsd">
    <wsse:UsernameToken>
      <wsse:Username>3</wsse:Username>
      <wsse:Password>SECRETO_DEL_GRUPO</wsse:Password>
    </wsse:UsernameToken>
  </wsse:Security>
</soapenv:Header>

Los clientes SOAP arman este header por ti: mira los ejemplos en Python y Node.js.

Operaciones

Los ejemplos usan el prefijo bil para el namespace del servicio (xmlns:bil="http://billing.tallerdeintegracion.cl") y omiten el header de seguridad.

getBankStatement

Saldo del grupo: facturas pagadas recibidas menos facturas pagadas emitidas hacia terceros, incluidos los intereses ya cobrados.

<soapenv:Body>
  <bil:getBankStatementRequest/>
</soapenv:Body>

<!-- respuesta -->
<BankStatement>
  <group>3</group>
  <balance>152000</balance>
</BankStatement>

getInvoices

Lista las facturas del grupo según su estado (pending o paid) y su lado: client (las que debes pagar) o supplier (las que emitiste o te cobran). El rango fromDate–toDate filtra por fecha de creación y no puede superar 3 días. 

<soapenv:Body>
  <bil:getInvoicesRequest>
    <bil:status>pending</bil:status>
    <bil:side>client</bil:side>
    <bil:fromDate>2026-11-18T10:00:00Z</bil:fromDate>
    <bil:toDate>2026-11-20T10:00:00Z</bil:toDate>
  </bil:getInvoicesRequest>
</soapenv:Body>

<!-- respuesta: cero o más BillingDetails -->
<BillingDetails>
  <id>507f191e810c19729de860ea</id>
  <client>3</client>
  <supplier>1000</supplier>
  <channel>fabric</channel>
  <description>...</description>
  <status>pending</status>
  <price>10000</price>
  <interest>300</interest>
  <totalPrice>10300</totalPrice>
  <createdAt>2026-11-18T10:05:00.000Z</createdAt>
  <updatedAt>2026-11-18T10:05:00.000Z</updatedAt>
</BillingDetails>

En una factura pending, interest y totalPrice reflejan el interés acumulado al momento de la consulta. En una paid son los valores cobrados al pagar.

emitInvoice

Emite la factura de una orden de compra cumplida. Responde con el BillingDetails creado.

<soapenv:Body>
  <bil:emitInvoiceRequest>
    <bil:order_id>507f191e810c19729de860ea</bil:order_id>
  </bil:emitInvoiceRequest>
</soapenv:Body>

payInvoice

Paga una factura pending de la que eres cliente. Se cobra el precio más el interés acumulado hasta ese instante, que queda fijado en la factura junto con la fecha de pago. 

<soapenv:Body>
  <bil:payInvoiceRequest>
    <bil:invoice_id>507f191e810c19729de860ea</bil:invoice_id>
  </bil:payInvoiceRequest>
</soapenv:Body>

Ejemplos de cliente

Para llamar al servicio necesitas un cliente SOAP: en Python el más usado es Zeep y en Node.js el paquete soap. Ambos leen el WSDL, exponen las cuatro operaciones como funciones y arman el header UsernameToken por ti. El usuario es el número de tu grupo y la contraseña es el mismo secreto que usas para generar tokens en Bodega y Órdenes de compra. Guárdalos como variables de ambiente (SOAP_USER y SOAP_PASSWORD) y no los imprimas ni los subas al repositorio.

getInvoices acepta un rango de máximo 3 días, así que estos ejemplos consultan las últimas 24 horas en vez de fechas fijas.

Python (Zeep)

pip install zeep
import os
from datetime import datetime, timedelta, timezone

from lxml import etree
from zeep import Client
from zeep.exceptions import Fault, TransportError
from zeep.plugins import HistoryPlugin
from zeep.wsse.username import UsernameToken

WSDL = 'https://dev.proyecto.2026-2.tallerdeintegracion.cl/soap/billing?wsdl'

history = HistoryPlugin()  # guarda el último sobre enviado y recibido
client = Client(
    WSDL,
    wsse=UsernameToken(os.environ['SOAP_USER'], os.environ['SOAP_PASSWORD']),
    plugins=[history],
)

print('Operaciones:', sorted(client.service._operations.keys()))


def call(operation, **params):
    """Llama a una operación y muestra el error del servidor si lo hay."""
    try:
        return getattr(client.service, operation)(**params)
    except Fault as e:  # el servicio respondió con un SOAP Fault
        # Zeep no siempre lee el texto del Fault (e.message puede ser None): si pasa,
        # muestra el sobre recibido, que trae el código y el motivo del error.
        detail = e.message or etree.tostring(history.last_received['envelope'], encoding='unicode')
        print(f'{operation}: {detail}')
    except TransportError as e:  # HTTP 401 (credenciales), 429 (rate limit), etc.
        print(f'{operation}: HTTP {e.status_code}')


# Saldo del grupo
statement = call('getBankStatement')
print(statement)

# Facturas pendientes que debo pagar, últimas 24 horas
now = datetime.now(timezone.utc)
invoices = call(
    'getInvoices',
    status='pending',
    side='client',
    fromDate=now - timedelta(days=1),
    toDate=now,
)
for invoice in invoices or []:
    print(invoice.id, invoice.supplier, invoice.price, invoice.interest, invoice.totalPrice)

# paid = call('payInvoice', invoice_id='507f191e810c19729de860ea')

Node.js (soap)

npm install soap
const soap = require('soap');

const WSDL = 'https://dev.proyecto.2026-2.tallerdeintegracion.cl/soap/billing?wsdl';

async function main() {
  const client = await soap.createClientAsync(WSDL);
  client.setSecurity(
    new soap.WSSecurity(process.env.SOAP_USER, process.env.SOAP_PASSWORD, {})
  );

  console.log('Operaciones:', Object.keys(client.describe().BillingService.BillingServiceSoapPort));

  // Saldo del grupo
  const [statement] = await client.getBankStatementAsync({});
  console.log(statement);

  // Facturas pendientes que debo pagar, últimas 24 horas
  const now = new Date();
  const [result] = await client.getInvoicesAsync({
    status: 'pending',
    side: 'client',
    fromDate: new Date(now - 24 * 60 * 60 * 1000).toISOString(),
    toDate: now.toISOString()
  });
  for (const invoice of result.BillingDetails || []) {
    console.log(invoice.id, invoice.supplier, invoice.price, invoice.interest, invoice.totalPrice);
  }

  // Emitir la factura de una orden cumplida (sólo el proveedor) y pagar una factura
  // const [invoice] = await client.emitInvoiceAsync({order_id: '507f191e810c19729de860ea'});
  // const [paid] = await client.payInvoiceAsync({invoice_id: '507f191e810c19729de860ea'});
}

main().catch(error => {
  // Un SOAP Fault (p. ej. credenciales inválidas) llega como error
  console.error('ERROR:', error.message);
  process.exit(1);
});

Si credenciales o permisos fallan, el servicio responde con un SOAP Fault (o HTTP 401): ambos clientes lo entregan como excepción, por eso conviene siempre envolver las llamadas en try/except (Python) o try/catch (Node.js).

Reglas de emisión

  • Sólo el proveedor de la orden puede facturarla.
  • La orden debe estar cumplida.
  • Se factura una sola vez por orden; emitirla de nuevo devuelve un error.
  • El monto es unit_price × quantity de la orden.
  • La factura nace pending. Sólo las órdenes de la tienda (cliente 999) se pagan solas; todas las demás, incluidas las ventas entre grupos en el mercado, las paga el cliente con payInvoice.

Intereses

Una factura impaga no genera interés durante las primeras 6 horas desde su emisión. Pasado ese plazo se cobra un 1% del monto por cada hora completa, interés simple (no se capitaliza). 

interés = máx(0, horas_completas_desde_emisión − 6) × 1% × precio
Tiempo desde la emisiónInterés sobre el monto
5 h 59 min0%
7 h1%
12 h6%
60 h54%

El interés se detiene al pagar. Una factura pagada antes de las 6 horas no paga interés; una impaga al cierre del período evaluado cuenta con el interés acumulado hasta ese momento.

Qué facturas recibe cada grupo

Tu grupo aparece como client (debes pagarlas) o como supplier (te deben) según el channel:

channelOrigenQuién emiteCliente
fabricCompras de insumos a la Farma CentralSe genera sola, supplier 1000Tu grupo
bufferCobro por hora del pulmónSe genera sola, supplier 2000Tu grupo
b2b, ftp, pubsubPedidos de clientes que despachasteTú (emitInvoice)El cliente de la orden
mercadoVentas entre grupos en el mercadoEl grupo vendedor (emitInvoice)El grupo comprador

Las facturas de costo (fabric y buffer) nacen pending y también corren los intereses: págalas a tiempo.
